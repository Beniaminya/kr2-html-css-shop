## Что мы сделали

### Структура проекта

- `index.html` — главная страница;
- `catalog.html` — каталог и фильтры;
- `product.html` — карточка отдельного товара;
- `order.html` — форма заявки;
- `contacts.html` — дополнительная страница контактов;
- `css/custom.css` — небольшие изменения стандартного оформления Bootstrap;
- `js/main.js` — логика форм, модального окна и каталога;
- `vendor/bootstrap/` — локальные CSS и JavaScript-файлы Bootstrap;
- `images/` — локальные изображения растений.

Содержание первой контрольной сохранено: магазин называется «Зелёный дом», используются те же растения, цены, изображения и вымышленные контакты. Главное изменение — интерфейс перестроен на Bootstrap.

### Локальное подключение Bootstrap

На каждой странице файлы подключаются в таком порядке:

```html
<link rel="stylesheet" href="vendor/bootstrap/css/bootstrap.min.css">
<link rel="stylesheet" href="css/custom.css">

<script src="vendor/bootstrap/js/bootstrap.bundle.min.js" defer></script>
<script src="js/main.js" defer></script>
```

`bootstrap.min.css` содержит стандартные классы фреймворка. `custom.css` идёт после него и поэтому может уточнять стандартные стили.

`bootstrap.bundle.min.js` управляет интерактивными компонентами: мобильным меню, модальным окном, accordion и tabs. Слово `bundle` означает, что в файл также включён Popper, который нужен некоторым компонентам Bootstrap.

`defer` откладывает выполнение JavaScript до завершения разбора HTML. При этом скрипты выполняются в том порядке, в котором подключены.

Локальное подключение отличается от CDN тем, что файлы лежат внутри проекта. Сайт продолжает работать без интернета, но обновлять Bootstrap нужно вручную.

## Краткий разбор новой информации

### Bootstrap

Bootstrap — CSS-фреймворк: набор готовых классов, компонентов и JavaScript-плагинов для быстрой сборки интерфейса. Он не заменяет HTML и CSS. Мы всё равно выбираем семантические теги, задаём содержимое и при необходимости пишем собственные стили.

Пример:

```html
<button class="btn btn-success">Заказать</button>
```

`btn` задаёт базовое оформление кнопки. `btn-success` выбирает зелёный вариант. Оба класса нужны одновременно.

### Сетка Bootstrap

Основная иерархия:

```text
container
└── row
    ├── col
    └── col
```

- `container` ограничивает ширину страницы, центрирует содержимое и добавляет боковые отступы;
- `row` создаёт строку;
- `col-*` создаёт колонки внутри строки;
- `g-*` задаёт промежутки между колонками и строками.

Bootstrap использует 12-колоночную систему. Например:

```html
<div class="row g-4">
  <aside class="col-12 col-lg-3">Фильтры</aside>
  <section class="col-12 col-lg-9">Товары</section>
</div>
```

На узком экране обе области имеют `col-12`, то есть занимают всю строку и располагаются друг под другом. Начиная с `lg`, фильтры занимают 3/12 ширины, а товары — 9/12.

### Mobile first и контрольные точки

Bootstrap проектируется от маленького экрана к большому. Класс без префикса действует всегда, а класс с префиксом начинает действовать с указанной ширины.

```html
<div class="col-12 col-md-6 col-lg-4">
```

- до `md` — 12/12, одна карточка в строке;
- с `md` — 6/12, две карточки;
- с `lg` — 4/12, три карточки.

Основные границы:

- `sm` — от 576 px;
- `md` — от 768 px;
- `lg` — от 992 px;
- `xl` — от 1200 px;
- `xxl` — от 1400 px.

### Utility-классы

Utility-класс делает одну небольшую вещь:

- `p-4` — внутренний отступ;
- `mb-3` — нижний внешний отступ;
- `d-flex` — `display: flex`;
- `gap-2` — промежуток между элементами;
- `fw-bold` — жирный текст;
- `text-secondary` — вторичный цвет текста;
- `shadow-sm` — небольшая тень;
- `rounded-4` — скругление;
- `h-100` — высота 100%;
- `w-100` — ширина 100%.

Буквы в отступах: `m` — margin, `p` — padding, `t` — top, `b` — bottom, `s` — start, `e` — end, `x` — горизонталь, `y` — вертикаль.

### Navbar и мобильное меню

```html
<nav class="navbar navbar-expand-lg">
  <button
    class="navbar-toggler"
    data-bs-toggle="collapse"
    data-bs-target="#main-navigation">
  </button>
  <div class="collapse navbar-collapse" id="main-navigation">...</div>
</nav>
```

`navbar-expand-lg` означает: до ширины `lg` меню свёрнуто, начиная с `lg` — раскрыто. Кнопка находит блок по селектору `#main-navigation`. Поэтому `data-bs-target` и `id` должны совпадать.

### Карточки

Карточка товара строится из `card`, `card-img-top`, `card-body`, `card-title` и `card-text`. Класс `h-100` делает карточки одной высоты внутри строки. Внутри `card-body` используется `d-flex flex-column`, а цена получает `mt-auto`: свободное место оказывается над ценой, поэтому кнопки разных карточек выравниваются.

### Badge и Alert

`badge` — маленькая метка: «Хит», «Новинка», «Скидка».

`alert` — заметное сообщение. В проекте alert используется для акции, подсказки, отсутствия результатов и успешной отправки формы.

`alert-dismissible` разрешает закрытие сообщения. Атрибут `data-bs-dismiss="alert"` сообщает Bootstrap, какое действие выполнить.

### Modal

Кнопка открытия:

```html
<button
  data-bs-toggle="modal"
  data-bs-target="#order-modal"
  data-product="monstera">
  Заказать
</button>
```

- `data-bs-toggle="modal"` выбирает тип компонента;
- `data-bs-target="#order-modal"` указывает окно;
- `data-product="monstera"` — наши собственные данные о выбранном товаре.

Bootstrap открывает окно, а наш JavaScript читает `data-product` и выбирает соответствующий пункт формы.

### Accordion и Tabs

Accordion показывает один раскрывающийся ответ. Он расположен на главной странице и используется для частых вопросов.

Tabs переключают части содержимого без перехода на другую страницу. На странице товара есть вкладки «Описание», «Уход» и «Доставка».

Это дополнительные Bootstrap-компоненты, которые повышают самостоятельную часть оценки.

### Формы

Bootstrap-классы формы:

- `form-label` — подпись;
- `form-control` — текстовое поле и `textarea`;
- `form-select` — выпадающий список;
- `input-group` — несколько связанных частей одного поля;
- `input-group-text` — текстовая часть группы, например `+7`;
- `form-check`, `form-check-input`, `form-check-label` — чекбокс;
- `invalid-feedback` — сообщение об ошибке.

HTML отвечает за смысл и правила проверки:

- `type="email"` проверяет формат e-mail;
- `required` запрещает пустое значение;
- `minlength="2"` задаёт минимальную длину;
- `pattern="[0-9]{10}"` требует десять цифр;
- `name` задаёт имя поля при передаче данных;
- одинаковые `for` и `id` связывают подпись с полем.

`novalidate` отключает стандартные всплывающие сообщения браузера. Проверка всё равно выполняется через `checkValidity()`, а ошибки оформляются классами Bootstrap.

### Зачем нужен JavaScript

Bootstrap JS управляет стандартными компонентами. Наш `main.js` добавляет логику конкретного магазина:

1. проверяет формы;
2. показывает сообщение об успешной отправке;
3. подставляет выбранный товар в modal;
4. фильтрует карточки каталога.

## Разбор main.js

### Проверка формы

```js
document.querySelectorAll(".needs-validation").forEach((form) => {
  form.addEventListener("submit", (event) => {
    event.preventDefault();

    if (!form.checkValidity()) {
      form.classList.add("was-validated");
      return;
    }
  });
});
```

- `querySelectorAll` получает все формы с классом `needs-validation`;
- `forEach` перебирает найденные формы;
- `addEventListener` назначает реакцию на отправку;
- `preventDefault` отменяет реальную отправку, потому что backend отсутствует;
- `checkValidity()` проверяет HTML-правила;
- `was-validated` включает Bootstrap-оформление ошибок.

У успешной формы читается `data-success`. По этому идентификатору находится alert, поля очищаются, а alert становится видимым после удаления `d-none`.

### Подстановка товара в modal

Событие `show.bs.modal` создаёт Bootstrap перед открытием окна. `event.relatedTarget` — кнопка, которая его открыла. Из `button.dataset.product` получается значение `data-product`.

```js
productSelect.value = button.dataset.product;
```

Значения `data-product` у кнопок совпадают со значениями `value` у `<option>`. Поэтому нужный товар выбирается автоматически.

### Фильтрация каталога

У каждой карточки есть данные:

```html
<div
  class="catalog-product"
  data-name="монстера"
  data-category="large"
  data-price="2400">
```

Функция фильтрации получает выбранные значения, сравнивает их с `dataset` карточки и вычисляет три условия:

```js
const isVisible = matchesSearch && matchesCategory && matchesPrice;
```

Если все условия истинны, карточка остаётся. Иначе добавляется класс `is-hidden`, которому в CSS соответствует `display: none`.

Это клиентская фильтрация: данные уже находятся в HTML, запрос к серверу не выполняется.

## Зачем нужен custom.css

Bootstrap даёт основу, а `custom.css` создаёт фирменный вид:

- зелёную цветовую схему;
- фон hero-блока;
- одинаковую высоту изображений;
- эффекты карточек при наведении;
- положение меток;
- оформление подвала;
- небольшие медиазапросы;
- прижатие футера к низу страницы.

Прижатие футера:

```css
body {
  display: flex;
  min-height: 100vh;
  flex-direction: column;
}

main {
  flex: 1;
}
```

`body` становится вертикальным flex-контейнером высотой не меньше окна. `main` занимает свободное место и отодвигает футер вниз.

## Возможные вопросы преподавателя

### Основы Bootstrap

**1. Что такое CSS-фреймворк?**  
Набор готовых CSS-классов, компонентов и соглашений, который ускоряет создание единообразного интерфейса.

**2. Почему выбран Bootstrap?**  
Он требуется в базовом варианте задания, содержит адаптивную сетку, готовые компоненты и хорошую документацию.

**3. Какие альтернативы существуют?**  
Tailwind CSS, Foundation, Bulma, UIkit и другие. В этой работе используется Bootstrap.

**4. Какая версия используется?**  
Bootstrap 5.3.8.

**5. Как Bootstrap подключён?**  
Локально: CSS и JS Bundle лежат в `vendor/bootstrap`.

**6. Чем локальное подключение отличается от CDN?**  
При локальном подключении файлы хранятся в проекте и доступны без интернета. CDN загружает их с внешнего сервера и уменьшает размер репозитория.

**7. Почему custom.css подключён после Bootstrap?**  
При одинаковой специфичности более позднее CSS-правило имеет приоритет, поэтому собственные стили могут переопределять стандартные.

### Сетка и адаптивность

**8. Для чего нужен container?**  
Он центрирует содержимое, ограничивает его ширину и добавляет горизонтальные отступы.

**9. Для чего нужен row?**  
Он объединяет колонки в строку и управляет их промежутками.

**10. Что означает col-12?**  
Колонка занимает все 12 частей строки, то есть всю доступную ширину.

**11. Что означает col-lg-3?**  
Начиная с ширины `lg` колонка занимает 3 части из 12, то есть четверть строки.

**12. Что такое контрольная точка?**  
Ширина экрана, с которой начинают действовать responsive-классы, например `md` или `lg`.

**13. Что значит mobile first?**  
Базовые правила рассчитаны на маленький экран, а классы `md`, `lg` и другие постепенно расширяют макет для больших экранов.

**14. Для чего нужен g-4?**  
Он задаёт горизонтальные и вертикальные промежутки между колонками строки.

**15. Чем g-*, gx-* и gy-* отличаются?**  
`g-*` меняет оба направления, `gx-*` — горизонтальные промежутки, `gy-*` — вертикальные.

### Компоненты

**16. Как работает navbar-expand-lg?**  
До `lg` меню сворачивается, а с `lg` отображается полностью.

**17. Почему мобильному меню нужен Bootstrap JS Bundle?**  
CSS отвечает за внешний вид, а JavaScript меняет состояние `collapse` при нажатии кнопки.

**18. Что делают data-bs-toggle и data-bs-target?**  
Первый атрибут выбирает Bootstrap-компонент, второй указывает связанный элемент по CSS-селектору.

**19. Для чего используется card?**  
Для повторяющихся самостоятельных блоков: товаров, преимуществ и контактных данных.

**20. Для чего используется badge?**  
Для короткой метки состояния или категории: «Хит», «Новинка», «Скидка».

**21. Для чего используется alert?**  
Для заметного сообщения пользователю: акции, ошибки, подсказки или подтверждения.

**22. Для чего используется modal?**  
Для показа диалога поверх страницы без перехода на другой HTML-файл.

**23. Какие дополнительные компоненты добавлены?**  
Accordion, tabs, breadcrumb, pagination и адаптивная таблица.

**24. Чем accordion отличается от tabs?**  
Accordion раскрывает вертикальные секции, а tabs переключают панели с помощью горизонтальных вкладок.

### Формы

**25. Для чего нужны form-control и form-select?**  
`form-control` оформляет текстовые поля и `textarea`, `form-select` — выпадающий список.

**26. Для чего нужен input-group?**  
Он объединяет части одного поля, например постоянный префикс `+7` и ввод оставшихся цифр.

**27. Для чего нужен form-check?**  
Для оформления checkbox или radio вместе с подписью.

**28. Чем id отличается от name?**  
`id` идентифицирует элемент на странице и связывает его с `label`. `name` задаёт ключ, под которым значение отправлялось бы на сервер.

**29. Для чего нужен required?**  
Он делает поле обязательным и участвует во встроенной HTML-валидации.

**30. Что проверяет pattern?**  
Соответствие значения регулярному выражению. В телефоне требуется десять цифр после `+7`.

**31. Что делает checkValidity()?**  
Возвращает `true`, если все правила HTML-валидации выполнены, иначе `false`.

**32. Почему форма не отправляет данные?**  
Это учебный frontend без backend. `preventDefault()` отменяет обычную отправку, а alert имитирует успешный результат.

### JavaScript проекта

**33. Что возвращает querySelectorAll?**  
Коллекцию всех элементов, соответствующих CSS-селектору.

**34. Что делает addEventListener?**  
Назначает функцию, которая вызывается при событии: `submit`, `reset`, `input`, `change` или событии Bootstrap.

**35. Что такое dataset?**  
Объект для чтения атрибутов `data-*`. Например, `data-price="2400"` читается как `element.dataset.price`.

**36. Что делает classList.toggle?**  
Добавляет или удаляет класс в зависимости от условия.

**37. Как работает фильтр каталога?**  
JavaScript сравнивает поисковую строку, категорию и цену с `data-*` карточки. Неподходящим карточкам добавляется `is-hidden`.

**38. Почему Number используется для цены?**  
Значения `dataset` являются строками. Для правильного числового сравнения цена преобразуется в число.

**39. Что такое Infinity в фильтре?**  
Это значение больше любого обычного числа. Оно используется, когда максимальная цена не выбрана, поэтому проходят все товары.

**40. Как товар попадает в modal?**  
В обработчике `show.bs.modal` берётся кнопка `event.relatedTarget`, читается её `data-product`, и это значение присваивается `select.value`.

### CSS и структура

**41. Зачем нужен собственный CSS, если есть Bootstrap?**  
Bootstrap даёт универсальную основу, а собственный CSS задаёт фирменные цвета, размеры изображений и несколько уникальных блоков.

**42. Как футер удерживается снизу?**  
`body` — вертикальный flex-контейнер с `min-height: 100vh`, а `main` имеет `flex: 1` и занимает свободное пространство.

**43. Почему используются семантические теги?**  
Они описывают назначение блоков, улучшают структуру документа и помогают средствам доступности.

**44. Для чего нужен alt у изображения?**  
Он текстом описывает изображение, если оно не загрузилось или страницу читает экранный диктор.

**45. Для чего нужны aria-label и aria-controls?**  
Они поясняют назначение элементов и связи между ними для вспомогательных технологий.

### Самостоятельная часть

**46. Какие самостоятельные доработки выполнены?**  
Локальное подключение Bootstrap, дополнительная страница контактов, работающие фильтры каталога, автоматическая подстановка товара, accordion, tabs, pagination, сообщения форм и дополнительная адаптивность.

**47. Что бы вы добавили при наличии backend?**  
Отправку формы на сервер, хранение заказов в базе данных, настоящий каталог из API и проверку данных на сервере.

**48. Почему клиентской валидации недостаточно для настоящего сайта?**  
Её можно обойти. Backend должен повторно проверять все входящие данные.
